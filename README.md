# Data Cleansing & ETL Pipeline: Loan Customer Data

A small end-to-end ETL (Extract, Transform, Load) project built in **Python (pandas) and SQLite**.
It cleans and validates a messy credit-style customer dataset and loads the result into a SQL database,
with a full audit trail of what was removed and why.

> **Note:** The dataset is **synthetic** (generated by `generate_data.py`). It contains no real people.
> It is deliberately messy to mimic problems common in financial and credit data.

## The problem
Raw file: **5,250 rows** with duplicates, three different date formats, phone numbers in four formats,
loan amounts like `GHS 12,500.00`, inconsistent casing (`ACTIVE`, `active `), region spelling variants,
missing values, invalid emails, underage customers, future dates and out-of-range credit scores.

## Pipeline
| Stage | What it does |
|---|---|
| **Extract** | Reads the CSV with every column as text so nothing is silently converted. |
| **Transform** | Trims whitespace and standardises case; maps region variants; converts 3 date formats to ISO (YYYY-MM-DD); normalises phones to `+233XXXXXXXXX`; strips `GHS` and commas from amounts; removes duplicate customer IDs. |
| **Validate** | **Reject rules** (record is excluded and logged with a reason): missing name, invalid date of birth, under 18, invalid or future loan date, missing or non-positive loan amount, invalid phone. **Flag rules** (record loaded, bad value set to NULL and flagged): missing or invalid email, missing or out-of-range credit score (valid range 300 to 850). |
| **Load** | Writes `clean_customers`, `rejected_records` and `etl_run_log` tables to SQLite, plus CSV copies. |

## Results
| Measure | Count |
|---|---|
| Rows extracted | 5,250 |
| Duplicates removed | 250 |
| Records rejected (failed a critical rule) | 442 |
| Clean records loaded | 4,558 |
| Loaded records with a quality flag (email or score nulled) | 657 |

Most common rejection reasons: missing loan amount (118), invalid phone (96), invalid date of birth (50),
under 18 (48), non-positive loan amount (46).

**Reconciliation check:** 5,250 − 250 − 442 = 4,558 loaded, which matches the database (PASS).

## SQL validation (`validation_queries.sql`)
After loading, SQL queries confirm that the clean table has: no duplicate customer IDs, no non-positive
amounts, no under-18 customers, no future loan dates, no malformed phones, no out-of-range scores, and only
3 status values and 7 regions. Every check returned 0 problems.

## How to run
```
pip install pandas
python generate_data.py       # creates data/customers_raw.csv
python etl_pipeline.py        # runs the ETL, creates output/customers.db
python run_validation.py      # runs the SQL validation queries
```
